# DUO-074 — Option Ollama Cloud

23 novembre 2026. Implémentation Codex ; lanceur et première version du guide
délégués selon le [contrat](../tasks/DUO-074.md), puis intégrés sélectivement.

## Périmètre livré

`--llm-backend local|ollama-cloud`, défaut local, et `--cloud-model gemma4:31b`.
Le choix par argument remplace le menu proposé, conformément à la demande.
Lanceur dédié, `OLLAMA_API_KEY`, HTTPS direct WinHTTP asynchrone. Les règles,
schémas et validations métier restent ceux du jeu, sans parseur de langage ajouté.

Le backend commun couvre toutes les finalités LLM. Validation stricte du
sous-ensemble de schémas utilisé par le jeu, une correction au maximum, délais
et budgets partagés par tour. Les erreurs de transport, de schéma et de contexte
empêchent la publication, même si un secours a été préparé. Les erreurs
sémantiques de prose conservent les secours établis du moteur.

Les réponses structurées sont retenues jusqu'à validation du schéma. Les
messages et tentatives exacts sont archivés, sans en-têtes secrets. Le nombre
d'appels inclut les corrections. Le cloud utilise une estimation par octets
et un plafond de contexte par défaut de 32 768 ; aucun poids local requis.
Les tokens rapportés restent distincts de cette estimation.

## Limites

Deux narrations SDL ont déclenché `voice_or_unvalidated_world_change`.
Les règles et l'état sont communs, les textes et mondes ne sont pas identiques
entre E4B local et 31B cloud. Pas de benchmark 30 interactions × trois graines,
de médiane/p95, ni de validation artistique exhaustive. Les six langues
conservent leurs chemins existants ; la recette cloud SDL couvre le français.
Les erreurs 429/5xx sont simulées ; le 401, l'annulation et le timeout sont réels.
Le premier contact invisible conserve les tests moteur existants, sans nouvelle
recette cloud spécifique. Le cloud reste expérimental.
