## Implémentation

Le réseau Gemma E4B est transcrit en opérations MLX C++, à partir de MLX-LM
0.32.2 (notice MIT incluse). Poids Safetensors affines 4 bits inchangés, 42 couches,
24 caches KV indépendants, partage KV, fenêtre glissante et embeddings par couche.
Le profil exact est épinglé : aucun support de modèles arbitraires n'est annoncé.
Le module MLX seul utilise C++20 ; moteur et interface restent C++17.

Deux points de fidélité/performance sont vérifiés dans le prototype : les
constantes scalaires conservent bfloat16 (les littéraux float C++ promouvaient
sinon les activations) ; le prefill évalue les caches KV seulement, sans calculer
les 18 dernières couches partageant ces caches pour des logits inutilisés.
La séquence greedy courte du prototype correspond à la référence. Les logits
ne sont pas annoncés bit-identiques : écarts d'arrondi bfloat16 observés.

llama.cpp fournit vocabulaire, template Jinja et grammaire, sans calcul GGML du
réseau dans cette variante. Le tokenizer GGUF extrait contient uniquement des
métadonnées (15 780 704 octets), dont le hash attendu est fixé dans le manifeste.
L'extracteur stdlib a reproduit ce hash depuis le vrai GGUF épinglé. Aucun poids
GGUF de 5,3 Go n'est embarqué dans la livraison MLX C++.

Poids résidents, cache neuf par requête, mutex commun, streaming contrôlé,
annulations coopératives, budgets et vérification SHA-256 restent en C++.
Les tailles/dates des fichiers résidents sont contrôlées avant réutilisation.
Les règles et validations du jeu ne changent pas ; pas de parseur de langue naturelle.
Les dépendances vendored restent inchangées.

## Mesures comparatives observées

macOS 14.1, Apple Silicon, 18 Go. Demandes et schémas utilisateur identiques,
seed 42, température 0 ; trois appels par processus, moyenne des deux derniers
pour le chaud. Mesures locales, sans purge disque ni isolation de la machine.

| Cas | MLX Python historique | MLX C++ | llama.cpp/Metal |
|---|---:|---:|---:|
| JSON thermique à chaud | 0,843 s | 0,864 s | 1,159 s |
| Narration, premier appel | 23,438 s | 20,387 s | 27,527 s |
| Narration à chaud | 15,095 s | 16,332 s | 22,553 s |
| Tokens finaux de la narration | 262 | 279 | 299 |

MLX C++ réduit de **27,6 %** la latence à chaud par rapport au backend C++
llama.cpp sur ce cas. Il reste **8,2 %** au-dessus de la référence Python sur
cette narration, avec **6,5 %** de tokens supplémentaires. Le JSON court est
proche (+2,5 %). Le premier appel natif MLX est plus rapide dans cette mesure.
Les prompts effectifs et samplers/grammaires diffèrent ; ne pas présenter ces
chiffres comme une comparaison à sortie identique ni promettre une stricte parité.
Le choix du backend le plus rapide porte sur les deux implémentations C++ mesurées.
