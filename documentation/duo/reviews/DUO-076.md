# DUO-076 — Échecs cloud en fin de partie

23 novembre 2026. Correctif Codex et comparaison runtime à la demande de l'auteur.

## Diagnostic observé

Partie `run-20261123T152344Z-1639461083`, modèle `gemma4:31b`, graine 1935587999.
Au tour 8 (EST), la carte narrative échoue : enveloppe Markdown, puis placement
d'indice malgré un schéma exigeant une liste vide. Les tours 16, 17 et 18
(SUD, OUEST, SUD), à 41,1 °C, échouent sur la passe littéraire facultative :
JSON invalide ou sortie tronquée à 220 tokens. Le sampling demandé vaut 4,307.
La géométrie et la proposition d'état avaient pourtant été acceptées. Le budget
cloud commun marquait toute erreur comme fatale, annulant aussi ces mouvements.
Il ne s'agit plus du dépassement de mémoire corrigé dans DUO-075.

## Correction et choix de modèle

- `cloud_optional_prose` n'est activé que pour `scene_hallucination_v1` et
  `player_prose_heat_v1`. Un contenu invalide, tronqué ou issu d'un canal privé
  reste rejeté mais ne condamne plus le tour : la prose préparatoire validée
  est conservée. Aucun texte refusé n'est montré. Réseau, authentification,
  annulation, délai, contexte et budget de tour restent fatals.
- Pour ces deux passes cloud, température envoyée plafonnée à 1. Les prompts
  conservent les étapes de dégradation thermique. Les demandes moteur et le
  sampling local restent inchangés ; l'archive distingue température demandée
  et payload envoyé. Les validations sémantiques restent actives.
- Toute correction de schéma reçoit le candidat rejeté et une température
  au plus égale à 0,2. Le candidat est compté dans le plafond de contexte.
  Seule une enveloppe Markdown JSON complète est retirée, avant validation
  intégrale ; aucun JSON n'est extrait d'un texte d'accompagnement.
  Les erreurs `anyOf`/`oneOf`/`allOf` détaillent les échecs de branches, avec
  leurs champs et les valeurs d'énumération autorisées, dans un message borné.
  Cela donne une contrainte exploitable à la correction sans modifier l'état.
- Défaut cloud : `deepseek-v4.1-flash`. Gemma reste accessible avec
  `--cloud-model gemma4:31b`. Défaut général local et modèle local inchangés.
  Ce choix vient des essais runtime ci-dessous, indépendamment du duo de
  développement. Aucun serveur Ollama local n'est requis par le jeu cloud.

Le catalogue et l'API directs ont été vérifiés :
[DeepSeek V4.1 Flash](https://ollama.com/library/deepseek-v4.1-flash),
[API chat](https://docs.ollama.com/api/chat). Aucun canal de réflexion privé
n'a été reçu dans la comparaison ; `think:false` est transmis.
