# REVIEW — MAC-002 — portage Apple Silicon / MLX

Date : 2026-10-28. Responsable : Codex. Branche : `macos-port`.
Décision : qualification technique locale ; limites artistiques et de distribution ci-dessous.

## Changements relus

Backend MLX exclusif de llama.cpp dans CMake ; arm64 ; worker Python local par
socketpair/posix_spawn, sans serveur. Modèle Gemma E4B Safetensors épinglé et vérifié,
contexte neuf, tokenizer réel, schéma dans le prompt et dans le masque de logits,
validation complète, annulation/délai et récolte du processus. Chemins `.app` et
Application Support. Installation, téléchargement atomique, build et bundle local.
Le code de navigation, inventaire, enquête et géométrie n'est pas modifié.

Deux corrections observées à l'exécution : le noyau de masque Outlines ne compilait
pas avec les logits bfloat16 de Gemma sous macOS 14, d'où masque float32 ; sa table
générique écrasait les alias de tokens et supprimait certains chiffres probables,
d'où construction d'une table conservant tous les IDs et les octets de fallback.
Les deux corrections sont dans le projet, aucune dépendance vendored n'est modifiée.

- 122 tests Python dans scripts + 4 dans tests réussis. Les 10 tests de protocole
  et d'intégrité livrés par DeepSeek sont revus dans MAC-003R1.
- Première inférence GPU réelle : réponse « Bonjour. » ; modèle vérifié et chargé.
- JSON contraint répété : deux succès, modèle non réutilisé puis réutilisé.
- `scripts/verify_mlx_runtime.py` exécuté sur le binaire final : ses cinq cas
  (réutilisation + JSON numérique, contexte, timeout, annulation, budget) passent.
  Résumé privé : `final-probes/summary.json`.
- Régression thermique après correction des alias : 37.0 valide, réponse française.
- Contexte insuffisant : `context_limit` ; budget d'un token : `token_limit` ;
  délai de 1 ms : `timeout` ; modèle absent : `model_missing` ; annulation :
  `cancelled`, sans réponse finale publiée. Ces tests utilisent le vrai binaire.
- SDL : démarrage français, huit images d'animation, sortie propre.
- Exploration vers l'est, seed 7 : lieu généré, narration et enquête acceptés,
  tablette de relevé placée par le modèle, image rendue et état sauvegardé.
- Depuis cet état : ouest, est, inventaire. Trois tours réussis sans secours ;
  entrée complète du lieu généré et inventaire identiques avant/après.
- Lancement du bundle depuis `/tmp`, ressources retrouvées, interprétation française.
  Le premier essai chronométré de 45 s a annulé la narration à la fermeture sans
  abandonner de worker ; il est conservé comme preuve d'annulation SDL.
- Essai final SDL de 75 s, français, depuis le bundle dans `/tmp` : un tour
  « regarder tout autour » accepté, narration complète française, seconde génération
  de huit vues ; archive fermée avec une commande, un lieu et aucune erreur.
- Réexécution de setup avec Python 3.12 et vérification intégrale des fichiers du
  modèle : réussies. La version Python 3.14 est refusée explicitement par le setup.
- Les sorties de build, poids, environnements et journaux restent ignorés/hors Git.
  Les fichiers locaux de l'utilisateur ne sont ni intégrés ni écrasés.

Le cache de dépendances Ninja a été abîmé par deux lancements de build se
chevauchant pendant la préparation. Codex l'a recompilé après `ninja -t recompact` :
le build suivant réussit et `ninja -n` indique « no work to do ». Aucun changement
produit pour contourner cette erreur d'orchestration.

## Limites factuelles

Un essai vers le nord, seed 42, a été refusé par le moteur après génération ;
il ne constitue pas une exploration réussie et ses règles n'ont pas été assouplies.
Les essais thermiques antérieurs à la correction des alias ont échoué et restent
dans les preuves. Le modèle peut toujours proposer des détails sémantiquement
invalides : le moteur les refuse. Les bornes flottantes du schéma sont contrôlées
après génération car Outlines ne les contraint pas toutes par masque.

La prose et les jonctions audio n'ont pas reçu de validation artistique humaine.
Une longue partie et toutes les langues ne sont pas qualifiées. Les quantifications
MLX/GGUF peuvent donner des sorties différentes. Windows n'a pas été recompilé
sur cette machine. Le bundle utilise Python, les poids et des bibliothèques locales :
il n'est pas autonome, notarialisé ni destiné à être déplacé vers un autre Mac.
Les options d'offload llama.cpp sont refusées par MLX, pas interprétées silencieusement.
